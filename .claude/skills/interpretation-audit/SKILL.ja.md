# 原典との突合

このリポジトリの決定のうち**外部の原典から導いたもの**が、原典のいまの言い分と一致しているかを
確かめ、[目録](../../../docs/reference/upstream-interpretations.md)を書き換える。

## いつ使うか

- 原典が動いた: 依存の major 更新、フレームワークのリリース、仕様の改訂。
- 外部の原典を引いている ADR を改訂した —— 対のこちら側が変わっている。
- 原典を読んで新しく決めたが、まだ行が無い。
- 目録がいつ真だったかを誰も言えなくなったときの定期の一回。

## 本スキルを使わない場面

- **変更のレビュー** —— `/impl-review`。
- **README とコードのずれ** —— `/back-prop`。あちらは宣言と自分の木の一致を問い、ここは宣言と
  **他人の言い分**の一致を問う。
- **依存の版の方針** —— `/tools-upgrade` が更新を採るかを決める。本スキルはその後で、更新が
  **何と言っているか**を読む。
- **どちらを動かすかの決定。** 下記のとおり、それだけは本スキルがしてはならない。

## Contract

| | |
| --- | --- |
| **持つもの** | 外部の原典と、そこから導いた決定との対、およびその対に対する 3 値の判定 |
| **しないこと** | 裁定。ADR を書き換えない。原典へ合わせよとも、逸脱を宣言せよとも言わない |
| **始まる契機** | 原典かこちらの決定が動いたとき、または対に判定が無いとき |
| **終わる条件** | 確かめた対すべてに判定と前提が付き、確かめていない対が確かめていないものとして名指されたとき |

## 手順 0. 範囲を決める

`AskUserQuestion` を 1 問。

```text
質問: どの対を確かめますか？
選択肢:
  - 目録に在る対をすべて  ← 既定
  - 特定の原典（依存の major 更新で動いたものなど）
  - 特定の決定（改訂した ADR から辿る）
  - 新しい対を足す（原典を読んで決めたが、まだ載っていないもの）
```

## 手順 1. 両側を、この実行で読む

記憶で判定しない。**書き留める前提は、人があなたを反証するために使うもの**なので、実際に開いた
ものから採る。

1. **原典。**リポジトリに同梱された写しを優先する（`node_modules/<pkg>/dist/docs/`、同梱された
   スキーマ、取り込んだ仕様）—— このリポジトリが実際に動かしている版に固定されているためである。
   オンラインにしか無いときは `WebFetch` し、URL と日付を記録する。
2. **こちら側。**目録の行が名指す ADR / 設計解説 / 設定ファイルを、全部。
3. **目録の行**と、そこに在る前提。**成り立たなくなった前提そのものが所見である** —— 判定は
   変わらないまま、その理由だけが消えていることがある。

**原典へ届かなかったとき、判定は「差異なし」ではない。**その行を未読として報告し、何を試したかを
述べ、前の判定を日付ごと残す。読めなかった原典は、同意した原典ではない
（[0157](../../../docs/adr/0157-inspection-declaration-discipline.md)）。

## 手順 2. 対ごとに 3 値のどれかを付ける

| 判定 | いつ |
| --- | --- |
| **差異なし** | いま読める原典が、こちらの決定が前提にしたことを言っている |
| **差異あり** | 食い違っており、**そう述べたこちらの決定が無い** |
| **逸脱宣言あり** | 食い違っているが、**なぜ外れるかをこちらの決定が述べている** |

**後ろの 2 つを分けることが、この目録の全部である。**標準から外れること自体は欠陥ではない ——
ADR [0010](../../../docs/adr/0010-standards-and-non-lockin.md) が在るのは、準拠が義務ではなく
判断だからである。欠陥なのは、**誰も知らないまま外れていること**である。

だから「差異あり」に着いたら、宣言が探していない場所に在らないかをもう一度見る —— 設定ファイル
のコメント、隣の ADR、`docs/rules.md`。決定から遠くに在っても宣言は宣言である。どこに在るかと、
その距離を述べる。

**手段を述べたコメントは、逸脱の宣言ではない。**「プレフィックスに大文字構成が混在するため
type-case を課さない」は道具の挙動を述べているだけで、**その体系が標準から外れていることも、
それでよい理由も**言っていない。

## 手順 3. 判定より先に前提を書く

行ごとに、**先に前提を書き**、それに照らして自分の判定を読む。順序が効く —— 先に書いた判定は、
それを支える前提を後から徴用する。

前提は、読み手が同じ作業を繰り返さずに反対できる形でなければならない。

- **引くか、位置を示す。**原典が実際に含んでいる一文か、正確なファイルと見出し。
- **版を名乗る。**どの版を読んだか —— 固定された写しの版、またはオンラインなら取得した日付。
- **こちら側のどこと突き合わせたかを言う。**決定はたいてい複数のことを言っており、判定はその
  1 つについてのものである。

前提を書けない対は**行を持たない**。確かめられなかった対として、何が足りなかったかとともに
報告へ回す。

## 手順 4. 目録を書き換える

[`docs/reference/upstream-interpretations.md`](../../../docs/reference/upstream-interpretations.md)
だけを書き換える。

- 行が指す **ADR / 設計解説 / 設定を書き換えない。**それらは監査の対象である。ここで直すと、
  監査と修正が同じ息で届き、**修正を誰も選んでいない**ことになる。
- 判定・前提・日付は**一緒に**更新する。古い前提の隣で日付だけが新しいと、行われなかった検査を
  主張することになる。
- 原典へ届かなかった行は、前の判定**と前の日付**を保つ。

そのうえで、行の形をゲートに掛ける。

```bash
pnpm exec vitest run --config vitest.scripts.config.ts scripts/interpretations.gate.test.ts
```

## 手順 5. 報告する

```text
## 原典との突合（<N> 対）

差異なし: <n> / 逸脱宣言あり: <n> / 差異あり: <n>
確かめられなかった対: <n>（<原典> —— <何が届かなかったか>）

### 差異あり（宣言の無い食い違い）
- <原典> ↔ <こちらの決定>
  - 原典: <前提。逐語または位置>
  - こちら: <該当する記述>
  - **どちらを動かすかは決めない。** 選べるのは 3 つ —— 原典へ合わせる / 逸脱を宣言する / 対そのものを外す

### 逸脱宣言あり（宣言が在る食い違い）
- <原典> ↔ <こちらの決定> —— 宣言の場所: <path>

### 未判定として残るもの
- <原典を読んで導いた決定のうち、まだ対になっていないもの>
```

**「差異あり」の塊に推奨を添えない。**3 つの選べる手を並べることは、その中から選ぶことではない。
どれが良いかを説明し始めたら、本スキルの範囲を出ている。

## 制約

- ✅ 両側を、この実行で、実際に開いたものから読む
- ✅ 行ごとに、判定より先に前提を書く
- ✅ 値は 3 つだけ —— 所見を和らげるために 4 つめを作らない
- ✅ 書き換えるのは目録だけ
- ❌ ADR / 設計解説 / 設定ファイルを書き換えない
- ❌ どちらを動かすかを推奨しない
- ❌ 届かなかった原典を「差異なし」にしない
