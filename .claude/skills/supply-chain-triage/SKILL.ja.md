# Supply-chain Triage

このスキルは、1 つの成果物の 1 つの版について 1 つの問いに答える ——
**この公開が侵害されたものである直接の証拠は在るか。**採点済みで出典付きの判定を出し、何も変えない。

在る理由は、セキュリティの ADR が記録している性質である ——
**窓は代理であり、代理は直接証拠で解除できる。**N 日待つことは 4 つの問いへの安い代わりであり、
**答えるほうが日数を数えるより強い。両方を飛ばすことだけが許されない。**

[0110](../../../docs/adr/0110-security-operations.md) が**その理由付けの正**である。
この段落を信じず**実行時に読む** —— 政策はそちらに住み、このスキルはその道具にすぎない。

最後の一節がここのすべてを形づくる設計上の制約である ——
**答えられなかった軸は、合格ではない。**判定は**得られた証拠についての主張**なので、
このスキルは「未回答」を明示し、**沈黙を低いスコアへ洗浄することを拒む。**

日本語参考訳はこのディレクトリの `SKILL.ja.md`（人間の参照用。スキルとしては読み込まれない）。
`references/` 配下のエコシステム別の手順は英語のみ —— **人が読む散文ではなくコマンドのレシピ**である。

## 使うとき

- 窓が候補を捕まえ、待つべきかを人が決める必要がある —— `tools-upgrade` が pending と分類した、
  `actions-pin` が step-back か保留になった、`images-pin` がタグで止まった。
- `make tools-cooldown-check` が `mise.toml` の pin で落ちた。**このゲートはビルドを落とす**ので、
  問いは「上書きがすり抜けたか」ではなく**「待つことが防御になっているか」**である。
- Dependabot のセキュリティ更新が窓を飛ばそうとしていて、**当日公開の版を取る価値があるか**を
  誰かが決めなければならない。
- 意図的な窓の上書きの前。**証拠も無く窓も待たないことが、[0110](../../../docs/adr/0110-security-operations.md)
  が唯一許さない組み合わせである。**
- 特定のリリースを取って安全かを、どんな言い回しであれ user が聞いた。

## Contract

| | |
| --- | --- |
| **Owns** | 1 つの版についての直接証拠の収集と採点、未回答軸の明示、判断者への引き渡し |
| **Never** | lockfile / pin / 窓の編集 / 版の採用 / 成果物の実行 / 取れなかった証拠を `0` に数えること |
| **Starts when** | 窓が候補を捕まえ、待つべきかを人が決める必要があるとき |
| **Stops when** | 4 軸を試み終えたとき。採点を渡して終わる —— 採用の判断はしない |

## このスキルを使わない場面

- 更新そのものの実行 —— `tools-upgrade` / `actions-pin` / `images-pin`、あるいは Dependabot の PR。
  このスキルは報告しかしない。
- 自前のコードの欠陥走査 —— `impl-review` と SAST のゲート。
- **可変タグの通常の保留。**可変タグの再ビルドでは 4 軸のうち 2 つがたいてい未回答になる
  （再ビルドには source の差分が無い）ので、トリアージは保留を解除するのではなく**追認する**のが普通である。
  判断が実際にそれを必要とするときだけ回す。

## 厳格な制限

**侵害されているかもしれない成果物に対してこのスキルを起動しても安全である理由が、この節である。**

- **報告のみ。**`mise.toml` / `.github/actions-pin.toml` / `docker/images-pin.toml` /
  `package.json` / `pnpm-workspace.yaml` / lockfile を決して編集しない。呼び出し元の resolve / apply を
  回し直さない。**自分で窓を下げない。低いスコアは判断者へ渡す証拠であって、判断ではない。**
- **成果物を決して実行しない。**取得して読む。install も build も run もしない。
  レジストリの package では **install script こそが攻撃**なので、tarball を取って展開する ——
  候補を `pnpm add` / `pnpm install` しない。**`pnpm dlx` もしない。**取得したバイナリを実行しない。
  検疫中のイメージを pull して run しない。
- **`npm` はここでは使えない。**[0001](../../../docs/adr/0001-package-manager.md) が pnpm を採用し
  npm を禁じているので、レジストリの照会は `pnpm view`、tarball の取得は `curl` で行う。
  `references/` のレシピはそれで書いてある。
- **リポジトリの木の外で作業する。**成果物はセッションの scratchpad へ展開し、**作業ツリーへは決して
  展開しない** —— 取ってきたものが誤ってコミットされないようにするため。
- **引くか、落とすか。**各軸のスコアは、その根拠になったコマンドと観測を伴う。
  **裏付けの無い勘は、スコアではなく未回答として報告する。**

## 4 つの証拠の軸

各軸を `0`〜`3` で採点する。このエコシステム / この成果物では証拠が得られないときは `?` を付ける。
**高いほど悪い。**各軸の取り方は `references/` のエコシステム別のレシピが持つ。

| 軸 | 問い | `0` はどう見えるか |
| --- | --- | --- |
| **P** 発行者 | 発行者は変わったか | 前の版と同じ維持者 / commit 者 / 所有者で、公開の頻度が履歴に沿う |
| **A** 出所の一致 | 成果物は出典と一致するか | provenance か透明性ログが成果物を名前の付いた source commit に結び付け、その commit が上流の既定ブランチに在る |
| **D** 変更内容 | 実際に何が変わったか | 前の版との差分を通読し、リリースノートに見合う量で、下記の署名を 1 つも含まない |
| **S** 依存 / 権限面 | 新しい依存や能力が現れたか | 新規の依存が無く、新しい `bin` / 実行の口 / 同梱パスが無く、権限が広がっていない |

**感触ではなく、証拠が言っていることで採点する。**

- `0` —— 答えられて、答えが継続性か無害な変更である。
- `1` —— 答えられて全体としては無害だが、説明の付かない細部が 1 つある。
- `2` —— 答えられて、リリースノートが説明していない何かがずれている。
- `3` —— 下記の侵害の署名が在る、または軸が不利に答えられた（発行者が未知のアカウントへ変わった、
  成果物がタグと一致しない、既に信頼しているタグが別の commit へ解決するようになった）。
- `?` —— 取得できない。**理由を 1 節で述べる。決して `0` で代用しない。**

**baseline は「これを断ったときに呼び出し元が持ち続ける版」である** —— いま pin されている SHA、
lock されている版、入っている版であって、単にレジストリ上の 1 つ前の release ではない。
答えている問いは「**移ることで何を引き受けるのか**」なので、**差分はいま検討している移動をちょうど跨ぐ**必要がある。

### 侵害の署名（軸 D の牙）

**これは悪意ある公開が実際に取ってきた形である。名指しで探す ——
「妥当そうか」で流し読みした差分は何も捕まえない。**

- **install / lifecycle の hook** が足された / 変えられた —— `preinstall` / `install` /
  `postinstall`、`action.yml` に `run:` の段が付いた。**誰かがレビューする前に実行されるコード。** <!-- skill-lint-ignore -->
  （このファイルは上流の Action のもので、このリポジトリには在りようがない。）
- **資格情報と秘密へのアクセス** —— `process.env`、npm の認証ファイル、クラウドの資格情報のパス、
  `GITHUB_TOKEN`、`ACTIONS_RUNTIME_TOKEN`、SSH 鍵、runner のメモリ。
- **新しい外向きの通信**。とくに生の IP、短縮 URL、paste サービス、webhook の受け口、
  そのプロジェクト自身の基盤と無関係なドメイン。
- **難読化** —— 他は読めるコードを配っている package の中の圧縮・minify されたソース、
  長い base64 / hex のリテラル、`eval` / `new Function`、文字列配列のデコーダ、
  異様なプラットフォーム判定の裏に隠されたコード。
- **プロセスの起動** —— 起動する理由の無いものの中の `child_process`、`curl | sh`。
- **ソースを追い越したビルド成果物** —— JS の action やビルド出力を同梱する package で、
  **ソースの変更を伴わない bundle の差分は、ここで得られる最も信号の強い所見**である。
  **走るのは bundle で、レビューされるのはソース**だからである。
- **同梱・能力の面の拡大** —— 新しい `files` / `bin` の項、新しい実行の口、足された `permissions`、
  新しいバイナリや blob。
- **不釣り合い** —— 「typo 修正」の release が 400 行の差分を運ぶ、2 年止まっていた package が
  1 日に 2 回公開する。

## 帯と、2 つの上書き

答えられた軸を合計する。

| 合計 | 帯 |
| --- | --- |
| 0–2 | **LOW** |
| 3–5 | **MEDIUM** |
| 6–8 | **HIGH** |
| 9–12 | **CRITICAL** |

**合計を上書きする規則が 2 つある。このデータに平均は誤った演算だからである。**

1. **どれか 1 軸が `3` なら、帯の下限は HIGH。**確定した赤旗 1 つは、きれいな 3 軸で薄まらない ——
   **侵害された公開は、たいてい payload 以外のすべてがきれいである。**
2. **未回答の軸は主張に上限を掛ける。**`?` が 2 つ以上 → 帯を出さず **INSUFFICIENT-EVIDENCE** と
   報告する。代理は解除されておらず、**窓はそのまま効く。**`?` がちょうど 1 つ → 帯は計算するが
   **MEDIUM で頭打ち**にする。LOW は 4 つの問いすべてに肯定的な証拠があると主張するもので、
   手元には 3 つしかないからである。

### 暴露面はスコアの隣に報告する。スコアへ畳み込まない

スコアが測るのは**この公開が悪意あるものである見込み**である。**どれだけ壊れるかは別の量**であり、
[0110](../../../docs/adr/0110-security-operations.md) は窓の長さが blast radius ではなく
**上流の検知レイテンシ**に比例すると明言している —— **混ぜると両方の数字が濁る。**
暴露面は別の行として報告する。

- **こちらのコードより先に、job の資格情報で CI の中で走る** —— GitHub Action、workflow が使う
  コンテナイメージ、install script を持つ package。最も高い。ここでの侵害は**秘密へ直接届く**。
- **ブラウザへ配られる、または動いているサーバへリンクされる** —— 実行時の依存。
- **ビルド / 開発時のみ** —— 生成器、linter、`mise` 管理の CLI。**エージェントスキルを配布する
  ツールはこの線の上ではなく、その上に座る** —— **開発者の権限で、リポジトリへの書き込み権を持つ
  ワークステーションの上で動き、何をマシン外へ送るかを自分で決める**
  （[0110](../../../docs/adr/0110-security-operations.md) §1.1）。

## 手順

### 1. 候補を確定する

証拠を集める前に、引数・呼び出し元の文脈・あるいは聞くことで、次を固定する。

| 欄 | 注 |
| --- | --- |
| エコシステム | `npm` / `github-actions` / `container-image` —— どの reference を読むかを決める。`mise` の pin はその backend のエコシステムへ振る |
| 名前と候補の版 | 検討している対象そのもの（タグ、版、digest） |
| baseline の版 | これを断ったときに呼び出し元が持ち続けるもの。差分のもう一方の端 |
| 窓 `N` と捕捉のされ方 | どの判定が発火したか、候補がいつ窓を抜けるか |
| 緊急度 | CVE が移動を強いているのか、定期の bump か。**スコアは変えない** —— 変えるのは、推奨が読み手にとって持つ値打ちのほうである |

baseline を決められないとき（初回の pin）はそう言う —— **軸 D はもう一方の端を失い**、
そのエコシステムが別の比較を提供しない限り `?` になる。

### 2. 該当する reference を読む

**当てはまる 1 つだけを読む。**それぞれが軸ごとのコマンドを与え、**そのエコシステムが答えられない軸**を述べる。

- [`references/npm.md`](references/npm.md) —— npm レジストリの package。`package.json` 経由でも、
  Dependabot の PR 経由でも、`npm:` backend の `mise` pin 経由でも同じ
- [`references/github-actions.md`](references/github-actions.md) —— `uses:` の参照。
  **3 つの中で最も証拠が厚い**（実在する commit 範囲が取れる）
- [`references/container-images.md`](references/container-images.md) —— イメージの digest。最も薄い

あわせて [0110](../../../docs/adr/0110-security-operations.md) §1.1 で当てはまる窓を読む ——
**ツールチェーンが既に保証しているものが、その軸が無料か不在かを決める。**

### 3. 集め、採点し、帯を出す

軸ごとに進め、**コマンドと、それが何を示したかを記録する。**そのうえで採点し、上書き規則を 2 つとも
当て、帯を導く。**4 軸を全部試みる前に採点しない** —— D で早々に `3` を見つけると P を飛ばしたくなるが、
**発行者の答えこそが、維持者に「そのアカウントを上流へ報告すべきか」を告げるもの**である。

### 4. 日本語で報告して止まる

下の報告を出し、呼び出し元へ返す（そちらが自分の確認を回す）か、終える。
**何も変えていないことを明示する** —— 読み手に「ファイルが動いたのか」と考えさせない。

```text
供給網トリアージ: <ecosystem>:<name> <baseline> → <candidate>
  捕捉理由: <disposition>（窓 <N> 日 / 公開 <publish-date>, <age> 日 / 解除 <clear-date>）
  緊急度  : <CVE 等 / 定期更新>

スコア: <sum>/12 → <BAND>
  P 発行者     : <0-3|?>  <根拠を1行、コマンド名を添える>
  A 出所の一致 : <0-3|?>  <同>
  D 変更内容   : <0-3|?>  <同>
  S 依存/権限面: <0-3|?>  <同>
  <override が効いた場合はその旨: 「D=3 のため HIGH で下限」「? が 2 つのため INSUFFICIENT-EVIDENCE」>

暴露面: <CI 資格情報 / 実行時 / ビルド時のみ>（スコアとは別軸）

所見:
  - <検出した具体物、または「該当署名なし」>

推奨: <下記の対応表に従う>

本スキルは何も変更していません（報告のみ）。採用の判断は <呼び出し元 / 利用者> が行います。
```

帯を推奨へ写す。

| 帯 | 推奨 |
| --- | --- |
| LOW | 4 つの問いは直接証拠で答えられており、窓の趣旨は満たされている。採用の可否は判断者に委ねる |
| MEDIUM | 既定は窓を待つこと。急ぐ理由があるなら、未解決の点を明示したうえで判断者が決める |
| HIGH / CRITICAL | 採用しない。上流への報告と、当該バージョンを避ける代替（1 つ前の aged 版）を検討する |
| INSUFFICIENT-EVIDENCE | 証拠が取れていないため窓がそのまま効く。待つ |

当てはまるときは壁を報告に書き直す —— **LOW のスコアは、塞がれた install を可能にしない。**

- **`pnpm-workspace.yaml` の公開年齢の窓**は resolver が強制し、その阻止は frozen-lockfile の
  再現にも及ぶ —— つまり resolve を回した機械だけでなく、**CI と他のすべての checkout へ届く。**
  版ごとの免除は在るので、採るか待つかは本物の選択になる ——
  **スコアはその入力として報告し、判断は呼び出し元に残す。**窓を下げること、strict を切ることを提案しない。
- **`make tools-cooldown-check` はビルドを落とす。**塞がれた pin は**このリポジトリが所有する検査**で
  塞がれており、LOW のスコアはそれを解除しない。逃げ口は
  [0110](../../../docs/adr/0110-security-operations.md) §1.1 が要求する免除のコメントで、
  **トリアージの判定はその理由欄に入る証拠であって、そのコメントを書く許可ではない。**
- **初回の pin には aged な戻り先が無い**ので、LOW でも「待つ」と「意図的な bootstrap」の選択が残る。

## 注記

- **きれいな報告は本物の結果である。**検疫された版のほとんどは、たまたま最近だっただけの普通の
  リリースである。**それを出典付きで言えることが、窓の中で CVE に対処することを可能にする。**
- **`?` は失敗ではない。**エコシステムによって証明できることが違うのは**構造上のこと**であり、
  その非対称は [0110](../../../docs/adr/0110-security-operations.md) が記録している。
  **正直に報告することがスコアを意味あるものに保つ。**
- **透明性ログが証明するのは不変性であって、無害性ではない。**公開の attestation は、成果物が
  公開後に差し替えられていないことを教える。**悪意を持って公開された版は、忠実に、検証可能に
  悪意を持っている。**軸 A が答えるのは、見た目より狭い問いである。
- **package の評判ではなく、その移動を採点する。**広く使われている package の侵害された release は
  このスキルにとって**普通の case** であり、ダウンロード数や star はこの版についての証拠ではない。
- **帰属は判定と同じくらい重要である。**HIGH / CRITICAL に着地したとき、軸 P と A で特定した
  発行者と commit が、**上流への報告を実行可能にするもの**である。含めること。
- **このリポジトリは公開されている。**所見が生きた指標を名指すときは、再現せず**形を述べる**。
  確定した侵害は、issue の本文へ届く前に私的に上げる。
- このスキルは commit も stage も push もしない。
